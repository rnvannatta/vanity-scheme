# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Vanity Scheme: a self-hosting R7RS Scheme-to-C compiler (`vsc`), interpreter (`vanity`), and runtime (`libvscheme.so`), targeting Linux, Windows (mingw), and wasm (emscripten). Cheney-on-the-MTA design, similar to Chicken Scheme. ~4 years old with archeological layering — some idioms are legacy (noted below).

The many loose `.scm`/`.c`/`.escm` files in the repo toplevel are the author's scratch files. Ignore them.

## Build & test

The build is self-hosting: `Makefile.all` compiles the compiler's `.scm` sources with the **installed** `vsc` (on PATH), not `bin/vsc`. The workflow is: build and test against `bin/vsc` until confident, and only then install.

```sh
make compiler -j8        # bin/vsc
make interpreter -j8     # bin/vanity
make runtime -j8         # lib/libvscheme.so
make tests_linux -j8     # normal smoke test: compiles & runs everything in test/
make tests -j8           # linux + windows (wine) smoke test
```

- **NEVER run `make install`, `sudo make hatch`, or `make lay_egg`.** Installing a bad compiler can wedge the bootstrap; these are user-only actions. Propose them, don't execute.
- No single-test target: compile and run one test manually, e.g.
  `bin/vsc -o /tmp/t test/vector.scm -O2 -Wc,-Llib -Wc,-Iinclude -Iinclude && LD_LIBRARY_PATH=lib /tmp/t`
  (tests expecting data files must be run from their own directory — the Makefile `cd`s to `dirname $test`).
- There are no emscripten tests yet; wasm smoke-testing is manual: `bin/vsc --platform=emscripten` on small files.
- `bootstrap/`, `build/`, and all `.scmh` files are autogenerated. Never hand-edit; not worth exploring.
- Makefile layout: `Makefile` is a dispatcher into `Makefile.all` (real rules), `Makefile.headers` (generates `.scmh` interface headers via `vsc -h`), `Makefile.bootstrap` (`hatch`: builds from checked-in C intermediates in `bootstrap/`). Source lists live in `Makefile.sources`; `config.mk` and `config/vanity/compiler/config.scm` come from `./configure`.

**Bootstrap-loop trap:** because the compiler compiles itself, some changes require multiple build→install cycles to take effect: adding new `##vcore.*` intrinsic symbols, and interface changes among interdependent `runtime/vanity/*.scm` libraries. Avoid creating such changes; flag them to the user when unavoidable.

## Compiler pipeline

Driver: `src/vanity/compiler/frontend.scm` (see the pipeline at its `RUN COMPILE` section). Stages, each a `(vanity compiler ...)` library in `src/vanity/compiler/`:

1. `expand.scm` — macro expansion / library resolution (`expand-toplevel`), then `alpha-convert.scm`
2. `cps.scm` — `to-cps`, plus `optimize` (which fuses basic-intrinsic calls into `basic-block` nodes)
3. `optimize.scm` — `qualify-callsites` at -O1+
4. `lower.scm` — `bruijn-ify` (de Bruijn variable indices), `to-functions` (procedure soup, explicit closures)
5. `transpile.scm` — `printout2` emits C, or `bytecode.scm` emits `.vasm` bytecode

Debugging aids: `vsc -E0/-E1/-E2` dumps post-expand / post-CPS / post-optimize IR; `-t` emits C; `--keep-temps` keeps intermediates; `--benchmark` times stages. The interpreter (`src/vanity/interpreter/frontend.scm`) runs the identical pipeline to bytecode and feeds `eval-vasm`.

Supporting modules: `variables.scm` (name mangling — `_V0` var, `_V40` FFI shim, `_V50` qualified function, etc., documented at top of file), `library.scm` (`.scmh` interface headers), `ffi.scm` + `src/ffi.y`/`ffi.l` (bison/flex C-header parser for `##foreign-import`), `blasphemy.scm` (the CL-LOOP-style `do-loop` expander), `hush.scm` (compile-time hashing for literal interning), `match.scm` (the pattern matcher used pervasively in the compiler).

**Two expanders:** `expand.scm` is the maintained path but under a feature moratorium — bugfixes only. New expansion features go to the in-progress hygienic scope-sets expander (`src/vanity/compiler/hygienic/`, SRFI-72-based, enabled via `--hygiene`), which will eventually replace it.

## Runtime

`runtime/` builds `libvscheme.so` (LGPL; `src/` compiler is GPLv2 — every file carries its license header, keep that in new files).

- `vruntime.c` — GC and core. Generational Cheney collector; on x86 the C call stack is the gen-0 nursery and GC longjmps back to the stack bottom. Under `VANITY_PURE_C` (emscripten) a dedicated nursery + trampoline bounces (`V_BOUNCE_FUNC`) replace deep stacks/longjmp. GC-recursion invariants are documented in comments near `VCheneyScan`.
- NaN boxing: `VWORD` encoding is documented at the top of `include/vscheme/vruntime.h`, along with the C-pointer type-info scheme for FFI foreign pointers.
- `vlibrary.c` — the bulk of the Scheme standard procedures. `vfiber.c` + `vfiber-*.S` — cilk-style fibers (continuation stealing; x86 only). `vapply-*.S`/`sicko.S` — per-ABI assembly (Intel syntax, `-masm=intel`). `vread.c` reader, `vbytecode.c` interpreter core, `wacky.c` FFI apply.
- The Scheme half of the runtime — `(vanity core)`, `(vanity list)`, etc. — lives in `runtime/vanity/*.scm` and `runtime/scheme/r7rs.scm`, compiled into the shared library.
- The transpiler emits code against the macros/inlines in `include/vscheme/vruntime.h` (`V_BEGIN_FUNC*`, `V_CALL`, ...); intrinsics are declared in `include/vscheme/vlibrary.h` via `V_DECLARE_FUNC*` metamacros. Every ABI macro has native and `VANITY_PURE_C` variants — new intrinsics must work under both.
- `SYSV_CALL` expands to nothing (failed mingw experiment). Don't add it to new code; removing it is welcome cleanup.

## The three intrinsic tiers

Documented in `docs/intrinsics.md`; understanding this is essential for runtime work.

1. `(##foreign.function "C" "decl")` — FFI shim; decodes/encodes only, no allocation.
2. `(##basic-intrinsic "VName" nargs)` — Basic ABI: `VWORD _VBasic_VName(VRuntime*, VEnv*, VWORD...)`. Fixed arity, may raise Scheme errors, **may not allocate Scheme objects**. Direct calls get fused by `optimize` into `basic-block` straight-line C with zero continuation garbage; `V_BEGIN_FUNC_BASIC` also generates a CPS wrapper so the value degrades gracefully when passed to `apply` etc.
3. `(##intrinsic "VName" nargs)` (also `min max` / `min +` arities) — full CPS ABI, first arg is the continuation. Required for variadics, anything that allocates, and control flow (call/cc).

**Prefer the `##intrinsic`/`##basic-intrinsic` string syntax for new intrinsics.** The legacy style — registering `##vcore.*` symbols in `runtime/vanity/intrinsics.scm` — requires multi-build-install bootstrap loops and is deprecated for new work.

## Language & style notes

- Mostly R7RS with deliberate breaks: no `dynamic-wind`; `+` raises on fixnum overflow rather than promoting. Extras: `match`, `do-loop`, `printf`/`sprintf`, fibers (`fiber-fork`, `fiber-map`, `async`/`await`). `IMPLEMENTED.md` tracks R7RS/SRFI coverage.
- Compiler Scheme style: heavy use of `match`, `cut`/`cute`, named-let loops; internal special forms are `##`-prefixed (`##vcore.*`, `##qualified-lambda`, `##letrec`, ...). Errors via `compiler-error` from `(vanity compiler utils)`.
- The compiler has no line numbers in errors and is frail to user typos — segfaults in compiler or generated code are bugs worth reporting, not shrugging off.
- `-g` gives generated executables a call-history printout on crash; names there are CPS artifacts (`global_k5`, `_V0foo_lambda1`).
